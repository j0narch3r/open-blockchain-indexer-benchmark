# Contour M1–M5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Contour — an elevation-optimized bicycle routing service and client for San Francisco, where effort (dominated by climbing) is the objective function and the effort/detour trade is the primary interaction.

**Architecture:** Two-stage routing. Stage A asks a routing engine for 6–10 diverse candidates; Stage B independently resamples each candidate's geometry at 10 m, samples a DEM via rasterio, computes true ascent/grade, scores flat-equivalent distance, applies a detour budget and diversity collapse, and returns the top 3 with generated explanations. Pure-function core (`effort`, `explain`), I/O isolated to `elevation` and `engines`, thin FastAPI shell.

**Tech Stack:** Python 3.12, FastAPI, uvicorn, rasterio, numpy, scipy, pyproj, shapely, pydantic v2, pytest, ruff, mypy. Expo (latest SDK) + TypeScript strict + expo-router + Zustand + TanStack Query + `@maplibre/maplibre-react-native` + react-native-svg. Docker Compose for GraphHopper/Valhalla.
